## N-045: compile against open documents (`internal/lsp/overlay.go`)

```
fs.ReadFile("home/me/site/_vars.styl")
        ├─ open in the editor? ──yes──▶ the buffer's text (saved or not)
        └─ no ───────────────────────▶ os.DirFS("/")
```

- `overlayFS` wraps the root DirFS: `Open` and `Stat` try the open
  buffers first (so an import of a buffer that was never saved resolves),
  and `ReadDir` delegates to the disk.
- **Deps.** It records every regular file the compile opens. Stat probes
  aren't counted. `analysis.deps` is the transitive set, so one pass
  finds every dependent.
- **Server.** `update` → `refresh(d)` + `refreshDependents(d)`, which
  re-analyzes each open document whose deps (or last good analysis's deps)
  include d. `didClose` refreshes dependents too, so closing an unsaved
  buffer reverts importers to the disk text. `didSave` still refreshes
  everything, to catch changes made on disk outside the editor.
- **Limit:** glob imports list directories from disk only, so a
  never-saved buffer isn't matched by `@import "dir/*"` until it's saved.

## N-046: references, rename, signature help, property completion, lint

**Use sites** (`refs.go`). Expressions have no positions, so the use
index is built in two steps:

1. From the AST, collect each statement's names (idents, call names,
   `{…}` interpolation in strings, selectors and properties, words in
   at-rule params) and attach them to the lines the statement owns. A
   statement owns its line up to the next statement's start; `else` lines
   are given to their If.
2. From the text (`codeMask`: comments and non-interpolated string text
   blanked, columns kept), take each word occurrence whose name is in its
   line's set. Definition sites are skipped, and so are words glued to
   `.`/`#`/`@`.

A declaration's property name at a statement start is a `Prop` use. It
resolves only to a function, because it's a transparent mixin call, and
never from inside that mixin's own body. `resolveUse` is shared by
references and lint.

**Symbol identity** (`symKey`). All root definitions of a name are one
symbol, in every file of a compile. A local is identified by file, scope
span, kind and name, so a parameter and a reassignment in the body are one
symbol.

**References/rename.** Every open document is treated as the root of a
compile, which spans the document and its import closure. When the target
def's file is in that compile, each file is indexed from its current text.
Its uses resolve against its own defs, then against the root defs of the
compile's other files. Imported partials share the root scope, so a
partial's use of another partial's variable is found. Results are
deduplicated across roots. `prepareRename` returns null for built-ins and
CSS words; `rename` validates the new name (`identRE`) and returns a
`WorkspaceEdit`.

**Signature help** (`sighelp.go`). On the cursor's masked line, the
innermost unclosed `(` and the word glued to it give the call, and commas
at its depth give the active parameter (a rest param absorbs the extra
arguments). Parameters are split out of the def's `Sig` text. Built-ins
return null (N-048).

**CSS property completion.** `atPropertyPosition` triggers on an indented
line, or after `{`/`;`, when only `[a-z-]` has been typed. The embedded
list (`cssProperties`) has about 300 standard properties.

**Lint** (`lint.go`, source `styl-lint`):

- **Duplicate property in one block** (warning). The consecutive fallback
  idiom with a different value is allowed; if/for bodies are separate
  blocks.
- **Unused local variable** (hint + Unnecessary tag). Skipped in sheets
  that call `lookup()`/`define()`.
- **Unused local function.**
- **Unused root function in an entry sheet**: not `_`-prefixed and not
  imported by any open document. It is checked against calls anywhere in
  its compile.
- **Deliberately not flagged:** root variables (`styl gen`, custom
  properties and partials make them public), parameters, and loop
  variables.

The repo's corpus (examples, testdata, difftest) lints clean. The one
false positive it turned up, transparent mixins, is what `Prop` uses fix.

Tests: `internal/lsp/refs_test.go`.

## N-047: `styl fmt` statement spelling (`internal/parser/respell.go`)

Runs on whichever layout passed the AST guard (`Format` → `respellSafe`).
It only touches lines where exactly one statement starts, and the parse
tells it which part of the line is the name, the operator and the value:

| rule | before | after |
|---|---|---|
| declaration colon spacing | `color:red`, `margin : 0` | `color: red`, `margin: 0` |
| declaration form | mixed | `prop: value` in braces; the file's majority in indentation syntax; a tie keeps each |
| assignment | `x=1`, `y  ?=2`, `obj.a=2` | `x = 1`, `y ?= 2`, `obj.a = 2` |
| parameter defaults | `m(a=1,b  =  f(1,2))` | `m(a = 1, b = f(1, 2))` |
| value commas | `f(1 ,2)`, continuation lines too | `f(1, 2)` |

- Selectors, at-rule params, strings and raw `url(...)` are never touched.
- `applyGuarded`: all edits at once if the AST holds. Otherwise it applies
  them one at a time and keeps each that holds (capped at 2000 edits). No
  real input has been found that needs the fallback: the parser still
  reads a colon-less declaration as one.
- **Mixed syntax:** `indentBraces` re-indents lines outside all braces with
  `bracesToIndent`'s stack rule (a braced header never adopts children),
  so outside lines are no longer left as written. A `{` on its own line
  sits at its header's level.
- `FuzzFormat` now also checks idempotency. It found three older
  stray-whitespace bugs, all fixed, with the inputs kept in
  `testdata/fuzz/FuzzFormat`:
  - a leading `\r` became indentation (`collapseSpaces` now drops leading
    whitespace);
  - a `\f`-only line was kept by `tidy` but blanked by `reindent` (both now
    use `TrimSpace`);
  - a `\r}` line wasn't seen as closing a block.
- All 36 corpus sheets were already canonical under the new rules.
