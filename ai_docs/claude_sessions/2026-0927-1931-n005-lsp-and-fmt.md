## `styl fmt` — `internal/parser/format.go`

**Key decision: fmt rewrites whitespace and never prints the AST.** The
parser strips comments before lexing (`stripComments`, see N-043) and keeps
no record of how an expression was spelled. Printing the AST back out would
lose comments. So `Format` works on the source lines and uses the parser's
own structure rules to decide each line's indentation.

- **Pipeline**: `tidy` (CRLF, trailing whitespace, blank-line runs → 1,
  no leading/trailing blanks, one final newline), then `reindent`.
- **Line classes** (`classifyLines`): blank, content, comment-only,
  block-comment continuation, object-literal continuation, trailing-comma
  continuation, and verbatim. Verbatim means code preceded by a comment on
  the same line: the parser measures indentation *after* removing the
  comment, so that line's indentation is left alone.
  - Block-comment state comes from a scan that follows `stripComments`'
    rules.
  - Object-literal spans come from `joinObjectLiterals`' opener rule
    (`objectLiteralLines`).
- **Indented syntax** (`indentTree`): the line-tree rule, with a stack
  popped while `old >= indent`, so depth = stack length. Comments take the
  depth of their own indentation without pushing a level.
- **Brace syntax** (`indentBraces`): uses brace open/close events from
  `scanStructural`, so interpolation and object braces are never counted.
  Line numbers are tracked through the text/interp/newline/skip handlers.
  - Inside braces, a line goes at header + 2, and a line starting with `}`
    goes level with the header.
  - Outside braces the indentation is structural in mixed files, so it is
    kept.
- **Continuation lines** keep their offset from the statement's first
  line (`relativeIndent`). Block-comment bodies shift by the same amount as
  their opening line.
- **`collapseSpaces`** collapses runs of spaces to one, skipping strings
  and any trailing comment. The gap before a trailing comment is preserved,
  so aligned comments stay aligned.
- **Guard**: the result must re-parse to an AST equal to the original.
  `sameAST` is a reflect walk that skips `Line`/`Col` and compares
  `Selectors`/`Params`/`Target` modulo whitespace runs. If the guard fails,
  fmt tries the tidy-only result, then returns `ErrFormatUnsafe`. A parse
  error is returned as is.
- **Public API**: `styl.Format` (`format.go`), with parse errors positioned
  via `compileErr`.
- **CLI**: `styl fmt [-w] [-l] [files]` (`cmd/styl/fmt.go`), gofmt-style.
  With no files it reads stdin.
- **Tests**:
  - `format_corpus_test.go` checks that the *full* reindent (not the
    fallback) keeps the AST, and that fmt is idempotent, for all examples,
    testdata and difftest corpus files.
  - `format_test.go`: golden cases and `FuzzFormat`. 45s of fuzzing ran
    5.2M execs with no failures.
  - Root `format_test.go`.

## LSP — `internal/lsp`, `cmd/styl-lsp`

- **`rpc.go`**: hand-rolled Content-Length framing via
  `textproto.ReadMIMEHeader`. Replies always carry a `result` (null
  becomes `json.RawMessage("null")`). Malformed JSON gets a -32700 reply
  and the server keeps serving.
- **`protocol.go`**: the LSP 3.17 subset used here, URI↔path conversion,
  and UTF-16 ↔ rune column conversion.
- **`server.go`**: single-threaded read loop, so documents need no locks.
  - Full sync (`change: 1`). `didSave` re-analyzes every open document,
    because imports compile from disk.
  - Each document keeps `lastGood`: while the current text is broken,
    hover, completion and definition use the last analysis that parsed.
  - `wordAt` treats `name(`/`+name` as a call, which picks whether the
    function or the variable is looked up first.
- **`analysis.go`**: `parser.Parse`, then `collectDefs` plus
  `importedDefs`, then `eval.ExtractManifest` inside an `eval.Sandbox`
  (1s deadline, 2M steps, 1 MiB values) over `os.DirFS(volume root)`.
  - The sandbox needs an FS for imports, hence the root DirFS.
    `fsLocation` maps OS paths to fs paths and `errDiag` maps them back.
  - An error in an imported file goes on the importer's first `@import`
    line, with `file:line` in the message. `ErrLimit` errors become
    warnings. `warn()` output becomes line-0 warnings.
  - Diagnostic columns are used only on tab-free lines, because AST/lexer
    columns are tab-expanded. Otherwise the whole line content is marked.
  - **Scope model**: each `def` carries the span of the scope it lives in.
    Function bodies, rulesets, at-rules and block mixin calls open a
    scope; if/for bodies don't; for-loop variables are scoped to the loop.
    A span ends at `lastLine`, the last statement start inside it, since
    the AST records where statements start but not where they end.
    `lookup` prefers, in order: the latest visible same-file def at or
    before the cursor (innermost scope on ties), then any visible
    same-file def, then an imported root def.
- **`symbols.go`**: the document outline, and hex color swatches.
  - Swatches are found only on value-statement lines, after
    `parser.StripComments` and string masking. A match followed by `{` is
    skipped. This keeps `#bad` selectors from being read as colors.
  - `colorPresentation` offers hex and `rgba()`.
- **New exports**: `eval.BuiltinNames`, `eval.ResolveImport`
  (`internal/eval/tooling.go`), and `parser.StripComments`.
- **Tests**: `server_test.go` drives the real `Serve` over `io.Pipe`s. It
  covers:
  - hover computed value (`gap = pad * 3` → `12px`)
  - definition across an import, and a local shadowing a global
  - completion (including an imported var's computed detail)
  - colors skipping an ID selector
  - symbols, formatting, and undefined-mixin / parse-error diagnostics
  - hover on broken text
  - an import-error diagnostic landing on the `@import` line
  - a nested runaway loop cut off as a warning

  A single `1..1e8` range didn't exercise the sandbox, because the
  existing 65536-item range cap catches it first. The suite passes under
  `-race`.
